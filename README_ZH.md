# llm-wiki-stack

[![npm version](https://img.shields.io/npm/v/llm-wiki-stack)](https://www.npmjs.com/package/llm-wiki-stack)
[![npm downloads](https://img.shields.io/npm/dt/llm-wiki-stack)](https://www.npmjs.com/package/llm-wiki-stack)
[![license](https://img.shields.io/npm/l/llm-wiki-stack)](LICENSE)

**将碎片化阅读转化为生长的概念网络。** 一套 Obsidian 知识库编译器——把原始素材转化为结构化、互联、可查询的知识，由 LLM 维护，由你的问题驱动。

---

## 解决的问题

你阅读。你收藏。你剪藏。你划线。几个月后，你有上百条笔记，但要找的时候找不到。找到了，又记不起它和其他内容之间的关联。你的笔记是散堆的，不是网络的。

大多数知识管理工具解决了"写"的问题，但没有解决"**合成**"的问题——把几十上百个来源的信息连接起来、调和冲突、追踪理解如何演进。

**llm-wiki-stack 解决的就是合成问题。**

## 如何工作

把它看作知识的**编译器**：源素材进去，结构化的概念网络出来。

```
01 raw/   ──编译──>  02 wiki/   ──对话──>  03 outputs/
(源笔记)             (概念网络)             (你的观点)
```

每层分工明确：

| 层 | 谁负责 | 做什么 |
|----|--------|--------|
| `01 raw/` | **你** | 存文章、剪藏、想法。LLM 绝不修改正文。 |
| `02 wiki/` | **LLM** | 提取概念，追踪理解演变，建立双向链接 |
| `03 outputs/` | **你 + LLM** | 你提问，LLM 揭示结构化关系，你写结论 |

结果：每个概念有一页。每页链接到出处。每条出处可追溯。每次理解的改变都记录下来。

## 快速开始

```bash
npx llm-wiki-stack
```

将在 `~/.claude/skills/` 下安装五个命令。然后在 Obsidian 仓库中打开 Claude Code：

1. **仅一次**：`/kb-init` — 初始化三层结构
2. **日常**：`/wiki-compile` — 将新 raw 笔记编译为 wiki 概念页
3. **有疑问时**：`/wiki-topic` — 提问，从你自己的笔记中获得结构化分析
4. **每月**：`/wiki-lint` — 体检报告：孤岛概念、脆弱依赖、概念演化时间线

试试这四个动作，如果觉得有用就继续。

## 命令

| 命令 | 角色 | 做什么 |
|------|------|--------|
| `/kb-init` | 架构师 | 初始化三层结构，生成 `AGENTS.md`，编译存量 raw |
| `/wiki-compile` | 编译器 | 从新 raw 中提取概念，执行独立性测试，建立交叉引用 |
| `/wiki-topic` | 分析师 | 基于问题合成观点——揭示因果链、矛盾张力、类比映射、合成假设 |
| `/wiki-lint` | 审计师 | 月度体检：断链、孤儿页、脆弱依赖、概念演化一览 |

## 让它运转的核心机制

### 概念独立性测试
每个新概念必须先"挣到"自己的页面。LLM 创建 wiki 条目前必须检查：
- **可定义性**——能否用一两句话（不含循环同义词）说清"这个概念是什么"？
- **单一核心**——这是一个概念，还是"A 与 B"的缝合？组合概念必须拆分。
- **多重验证**——是否来自至少两个不同源笔记，且各有独立论述角度？

这防止了知识库的两种常见病：过泛化的标签（"技术""社会"）和过特异的一次性概念。

### 概念演化（永不覆盖）
新信息默认**追加**。只有新证据**明确纠正**了旧事实错误时，才更新核心定义——并且旧理解会被归档到"概念演化"区，附上时间戳。观点冲突并列在"不同理解"区。你的思想史被保留，不被抹去。

### 交叉引用完整性
每条陈述链接到 raw 出处。每个 wiki 链接双向。每次编译验证 `linked_count`。断链在体检报告中标记。没有隐藏状态——一切都是带 YAML frontmatter 的纯 Markdown。

## 设计原则

- **连线成网**——碎片信息 → 有机组织 → 个人观点
- **人判断，LLM 编译**——你负责创意、判断、提问；LLM 负责编译、链接、体检
- **奥卡姆剃刀**——复杂度不超出"文件夹 + Markdown + Obsidian 原生能力"
- **复利效应**——知识编译一次，持续沉淀增值
